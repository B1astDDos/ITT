# ClassroomBooking

Учебный WPF-проект по практическим работам **№4** (конфигурация) и **№6** (журнал
событий и служба поддержки).

Платформа: **.NET Framework 4.7.2**, язык: **C# 7.3**, среда: **Visual Studio 2022**
(проект открывается и в более новых версиях Visual Studio).

---

## 1. Как открыть и запустить

1. Откройте файл `ClassroomBooking.sln`.
2. При первом открытии Visual Studio может предложить установить
   «Пакет средств разработки .NET Framework 4.7.2» — согласитесь.
3. Соберите решение: **Ctrl+Shift+B**.
4. Запустите: **Ctrl+F5**.

После запуска:

* заголовок окна — `Classroom Booking — Учебная конфигурация`;
* `StatusTextBlock` — `Учебный режим`;
* в `bin\Debug` рядом с `ClassroomBooking.exe` лежит `appsettings.json`.

Если заголовок и статус другие — проверьте, что `appsettings.json` скопирован в
`bin\Debug` (свойство файла **Копировать в выходной каталог = Копировать, если новее**).

```

    │   └── Booking.cs
    ├── Services/

    │   ├── UserService.cs
    │   ├── RoomService.cs
    │   ├── BookingService.cs
    │   └── SupportLogger.cs        — журнал INFO / WARNING / ERROR

    ├── configs/
```

Ссылка **System.Web.Extensions** уже подключена в проекте (Обозреватель решений →
Ссылки). Именно она даёт `JavaScriptSerializer`, потому что в .NET Framework 4.7.2
нет встроенного `System.Text.Json` из современного .NET.

## 3. ПР №4. Конфигурация

### Параметры (`appsettings.json`)

| Параметр | Тип | Учебное значение | Назначение |
|---|---|---|---|
| `AppTitle` | string | Classroom Booking — Учебная конфигурация | Заголовок окна |
| `WorkDayStart` | string | `08:00` | Начало рабочего времени |
| `WorkDayEnd` | string | `20:00` | Конец рабочего времени |
| `MinBookingMinutes` | int | `30` | Минимальная длительность |
| `MaxBookingHours` | int | `4` | Максимальная длительность (самостоятельное задание) |
| `AllowUnavailableRooms` | bool | `false` | Разрешение недоступных аудиторий |
| `AllowPastDates` | bool | `false` | Разрешение прошедших дат (самостоятельное задание) |
| `AdminMode` | bool | `false` | Режим администратора (самостоятельное задание) |
| `StatusMessage` | string | `Учебный режим` | Статус при запуске |

### Как это работает

`ConfigService.Load()`:

1. берёт папку запуска `AppDomain.CurrentDomain.BaseDirectory`;
2. через `Path.Combine` получает путь `appsettings.json`;
3. проверяет файл через `File.Exists` (нет файла — значения по умолчанию);
4. читает текст `File.ReadAllText`;
5. разбирает JSON через `JavaScriptSerializer`;
6. при повреждённом JSON `try/catch` возвращает `new AppSettings()`
   (поведение из п. 30 практики).

`MainWindow` получает настройки и применяет:

```csharp
settings = configService.Load();
Title = settings.AppTitle;
StatusTextBlock.Text = settings.StatusMessage;
```

В `BookButton_Click` из настроек берутся:

* рабочее время (`TimeSpan.TryParse` + проверка диапазона);
* минимальная и максимальная длительность;
* доступность аудитории (`AllowUnavailableRooms`);
* прошедшая дата (`AllowPastDates`);
* стартовое сообщение (`AdminMode`).

При некорректном `WorkDayStart`/`WorkDayEnd` приложение **не падает**, а выводит
`Ошибка конфигурации рабочего времени.`

### Переключение конфигураций

**Рабочая конфигурация (09:00–18:00, минимум 60 минут):**

1. Откройте `configs\appsettings.work.json`.
2. Скопируйте его содержимое в `appsettings.json` проекта.
3. Пересоберите (**Ctrl+Shift+B**) и запустите.
4. Заголовок — `Classroom Booking — Рабочая конфигурация`, статус — `Рабочий режим`.

Быстрая проверка без пересборки: измените файл прямо в `bin\Debug\appsettings.json`
и запустите `ClassroomBooking.exe` (C# при этом не меняется).

> При обычной сборке файл из проекта копируется в `bin\Debug` только если он новее
> (`PreserveNewest`), поэтому правки в `bin\Debug` сохраняются до изменения
> исходного `appsettings.json`.

### Таблица проверок (учебная конфигурация)

| Проверка | Данные | Ожидается |
|---|---|---|
| До рабочего времени | 07:30–09:00 | `Бронирование доступно с 08:00 до 20:00.` |
| После рабочего времени | 19:00–20:30 | `Бронирование доступно с 08:00 до 20:00.` |
| Короткая бронь | 10:00–10:15 | `Минимальная длительность — 30 минут.` |
| Корректная бронь | 10:00–11:00 | `Бронирование создано.` |
| Недоступная аудитория | Room 305, 10:00–11:00 | `Аудитория недоступна для бронирования.` |

### Рабочая конфигурация

| Проверка | Данные | Ожидается |
|---|---|---|
| До рабочего времени | 08:30–10:00 | `Бронирование доступно с 09:00 до 18:00.` |
| Короткая бронь | 10:00–10:30 | `Минимальная длительность — 60 минут.` |
| Корректная бронь | 10:00–11:00 | `Бронирование создано.` |
| Пересечение | 10:00–12:00, затем 11:00–13:00 в той же аудитории | `На это время аудитория уже забронирована.` |

### Дополнительные проверки

| Проверка | Настройка | Ожидается |
|---|---|---|
| Недоступную аудиторию можно бронировать | `"AllowUnavailableRooms": true` | `Бронирование создано.` |
| Превышение лимита | 10:00–15:00 при `MaxBookingHours: 4` | `Максимальная длительность — 4 ч.` |
| Прошедшая дата | вчерашняя дата при `AllowPastDates: false` | `Нельзя бронировать прошедшую дату.` |
| Режим администратора | `"AdminMode": true` | статус `Режим администратора` |
| Ошибочная конфигурация | `"WorkDayStart": "утро"` | `Ошибка конфигурации рабочего времени.` |

## 4. ПР №6. Журнал и служба поддержки

### Журнал событий

Путь: `%LocalAppData%\ClassroomBooking\Logs\application.log`
(Win+R → `%LocalAppData%` → `ClassroomBooking` → `Logs`).

Формат строки:

```
2026-11-11 21:43:05 [INFO] Запуск приложения. Режим: Учебный режим; Время: 08:00-20:00
```

Что пишется:

| Уровень | Событие |
|---|---|
| INFO | запуск приложения с параметрами конфигурации |
| INFO | пользователь начал создание бронирования |
| INFO | бронирование успешно создано |
| WARNING | не выбран пользователь / аудитория / дата |
| WARNING | аудитория недоступна, время вне рабочего периода, короткая или длинная бронь |
| WARNING | обнаружено пересечение бронирований |
| ERROR | непредвиденное исключение (с полным `ex.ToString()`) |

`SupportLogger` — статический класс; ошибка записи журнала перехватывается и
**никогда не закрывает приложение**.

### Проверка ERROR (учебный сбой)

1. В `BookButton_Click` внутри `try` перед `bookingService.AddBooking(booking)`
   временно добавьте:
   `throw new Exception("Учебная проверка журнала ошибок");`
2. Соберите и нажмите «Забронировать».
3. В журнале появится запись `[ERROR]`, пользователь увидит
   `Не удалось выполнить операцию. Обратитесь в поддержку.` (без трассировки).
4. **Удалите строку `throw`** и пересоберите проект.

### Окно «Сообщить о проблеме»

Кнопка `Сообщить о проблеме` в главном окне открывает `SupportRequestWindow`.

* Пустые тема или описание не сохраняются (предупреждение).
* Иначе создаётся файл `%LocalAppData%\ClassroomBooking\SupportRequests\SUP-ГГГГММДД-ЧЧММСС.txt`.
* В файле: `ID`, `Дата`, `Версия`, `Тема`, `Описание`, `Журнал`.
* В `application.log` добавляется `INFO — Создано обращение пользователя: SUP-...`.

## 6. Примечания

* Бронирования хранятся **в памяти**: после закрытия приложения список пуст —
  это ожидаемое поведение учебного прототипа.
* Синтаксис проекта ограничен **C# 7.3** (как требует практика): не используются
  `is not` и file-scoped namespace.
* `System.Text.Json` и NuGet-пакеты не нужны.
* Для полной проверки «с нуля»: удалите `bin` и `obj`, затем **Сборка → Пересобрать
  решение**.
